# ドキュメントのスコープ
本ドキュメントは以下をスコープとする。

* コンテンツストレージの要件

コンテンツファイル及びXMPサイドカーファイル自体のフォーマットについては[content_files.md](./content_files.md)で定義する。


# コンテンツストレージが満たすべき要件
コンテンツストレージは以下の要件を満たす必要があり、逆にこれらの要件を満たす限り具体的な実装は選択可能である。

* ポータビリティを第一に考え、下記に示すようにエクスポートできること
* コンテンツ配信エンドポイント経由でのコンテンツファイルHTTP配信時に、、クライアント側での特殊な復元処理なしで、適切なContent-Typeを持つコンテンツファイルのバイト列を取得できること
  * Rangeリクエストやキャッシュの制御など、静的ファイル配信において一般的に必要とされる機能を可能な限り実装していることが望ましい
* バックエンドAPIサーバーからのアクセスにおいて、下記に示すような操作が行えること

要件を満たす限り、実際の内部表現において圧縮・暗号化・分割などを行うことは許容する。
また、コンテンツストレージは単体のコンポーネントである必要はなく、あくまでも外部とのインタフェースが要件を満たす限り、内部的に複数のコンポーネントから構成されていても良い。

# エクスポート要件
コンテンツストレージは、コンテンツファイル及びXMPサイドカーファイルを、通常のツールで扱える以下のようなファイル名の標準ファイルとしてエクスポートできる必要がある。

```
コンテンツファイル: {コンテンツファイルの識別子}.{コンテンツファイルの拡張子(小文字)}
XMPサイドカーファイル: {コンテンツファイルの識別子}.xmp
```

# バックエンドAPIサーバーからの操作要件
コンテンツストレージは、バックエンドAPIサーバーにおける処理を念頭に、以下の操作を行える必要がある。

* コンテンツファイル及びXMPサイドカーファイルの列挙
* コンテンツファイル及びXMPサイドカーファイルに対するCRUD操作
* XMPサイドカーファイルに対するバージョン情報の取得
  * ここでいうバージョン情報は[tag_parse.md](./tag_parse.md)で定義される検索用DBの更新判定に利用できるものであり、必ずしもバージョンそのものである必要はなく、例えばタイムスタンプ等でも良い
