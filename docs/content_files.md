# ドキュメントのスコープ
このドキュメントは以下をスコープとする。

* 対応するコンテンツファイルフォーマット
* コンテンツファイルの識別子
* タグの定義
* コンテンツファイルとタグの対応付け
* タグスキーマの概念
* コンテンツの異常

コンテンツファイルが具体的にどのように保存され物理的に表現されるかについてはこのドキュメントのスコープ外とし、[content_storage.md](./content_storage.md)で定義する。

# コンテンツのファイルフォーマット
## 設計思想
広範なファイルフォーマットをサポートするのではなく、圧縮効率と実装のシンプルさを踏まえて必要最低限のフォーマットのみの対応とする。

ただしこれだとユーザビリティが下がるため、上記はあくまでもファイル保持と閲覧という代表的なフローにおける正規形式に適用する。
移行やインポートの際に変換を行うことで、ユーザビリティを保ちつつ内部実装やファイル保持をシンプルにする。
変換を行った場合は変換後のファイルを本システムにおける正規コンテンツとし、取り込み元ファイルは本システムの管理コンテンツとしては扱わない。

## 画像・アニメーション
画像ファイルに関しては、正規形式としては[AVIF](https://aomediacodec.github.io/av1-avif/)のみ対応するものとする。

ただし、インポートや移行において一般的なファイルフォーマットに対応することを妨げない。

# コンテンツファイルの識別子
コンテンツファイルの識別子は、[RFC 9562](https://datatracker.ietf.org/doc/html/rfc9562)によって定められるUUID v4を用いた以下のようなフォーマットとする。
文字列表現には、16進数を8桁・4桁・4桁・4桁・12桁に区切ったハイフン付きの形式を使用する（例: `2f1c75fc-55de-4d4b-8992-76050f65dff0`）。

```
{UUID v4}
```

# コンテンツファイルとタグの対応付け
タグは[XMP](https://developer.adobe.com/xmp/docs/)の形式を取り、コンテンツファイルに埋め込むのではなく、サイドカーとして同一のUUIDを持つ別のポータブルなメタデータファイルとして表現する。
また、その識別子はコンテンツファイルの識別子と同一のUUIDを用いる。

つまり、

```
コンテンツファイルの識別子: {UUID v4}
タグファイルの識別子: {UUID v4}
```

というフォーマットとする。

これらのファイルの具体的な配置は保存基盤に依存する。
また、メタデータファイルは取り込み前を除いて必ず存在する必要がある。

# タグの定義
## タグの設計思想
タグは、内部表現であるXMPのサブセットを使って表現する。

対応するタグは、XMPのSimple Property及びArray PropertyのみとしStructured Propertyには対応しない。

## XMPの名前空間

プロパティ名つまりタグ名は独自の名前空間を1つだけサポートし、指定された名前空間以外のプロパティをこのアプリケーションにおけるタグ用のプロパティとしては扱わない。
ただし名前空間はデプロイ時に指定できるものとする。

## タグ名

同一コンテンツ内のタグ名は一意でなければならず、同じタグ名を持つタグの重複は認めない。
値や型が異なる場合も同様とする。1つのタグ名に複数の値を持たせる場合は、Unordered Arrayを使用する。

実質的なタグ名となるプロパティ名のlocal nameは、有効なUTF-8文字列である必要がある。
また、デコードした後のUnicodeコードポイント列はUAX #15で規定されるNFKCで正規化されており、以下の条件を満たしていなければならない。

```
^<XID_Start><XID_Continue>{0,63}$

ただし、
XID_Start: Unicode UAX #31におけるXID_Startに属するコードポイント
XID_Continue: Unicode UAX #31におけるXID_Continueに属するコードポイント
```

参考:
* [UAX #15](https://www.unicode.org/reports/tr15/)
* [UAX #31](https://www.unicode.org/reports/tr31/)

## タグの値
タグの値としては、XMPにおける以下の形式をサポートする。

```
Property formとしては、
* Simple
* Unordered Array

Data Typeとしては、
Simple:
  Text | Integer | Real

Unordered Array:
  Text | Integer | Real

ただし、
* Textは長さが1以上255以下の有効なUTF-8文字列とし、デコード後のUnicodeコードポイント列はUAX #15で規定されるNFCで正規化されている必要がある。長さはUnicodeコードポイント数で数える
  * 例外として、Simple Propertyかつ値が長さが0の文字列の場合のみは、キーのみのタグとして扱う。Unordered Arrayの要素に空文字列は許可しない
* IntegerはJavaScriptのnumberで安全に扱える整数範囲である-9007199254740991以上、9007199254740991以下（±(2^53 - 1)）である必要がある
* RealはXMPのRealの字句形式に従い、IEEE 754 binary64の有限値として変換可能である必要がある
* Unordered Arrayのすべての要素は同一のData Typeである必要があり、値の重複は許容しない
  * Realの値の重複は文字列表現ではなく変換後の数値で判定する。例えば1.0と1.00、0.0と-0.0はそれぞれ同じ値として扱う。
```

# タグスキーマ
タグスキーマは、コンテンツのタグに対して明示的な定義を定める。

明示的な定義があるタグは、その定義に従ってXMPの値を解釈する。
タグスキーマが設定されていない場合または定義されていないタグを許容する場合において、明示的に定義されていないタグについてはフォールバックとして、XMPのSimple PropertyをキーのみのタグまたはTextタグ、Unordered ArrayをTextのセットタグと解釈する。
この際、値の字句だけからIntegerやRealの型を推測しない。
つまり、例えば`1.0`という値のタグであったとしてもRealではなくTextとして解釈する。

上記の解釈に失敗したタグは有効なタグに含めず後述の異常として扱う。

# コンテンツの異常
[tag_parse.md](./tag_parse.md)に記載の処理フローに従って正常に取得したコンテンツについて、メタデータの異常はコンテンツの診断情報として扱い、それをもってコンテンツ自体を無効とはしない。
有効なコンテンツにおいて、異常があるタグは有効なタグとしては扱わず、検索の対象としては扱わない。

異常の種類は以下の通りである。

| 異常 | スコープ | 条件 |
| --- | --- | --- |
| `InvalidKey` | 単一タグ | XMPプロパティ名がタグキーの条件を満たさない |
| `DuplicateKey` | 単一タグ | 同じタグキーのXMPプロパティが複数存在する |
| `UnsupportedXmpValueType` | 単一タグ | XMPの値がStructured Propertyや順序付き配列など、タグとして対応しない形式である |
| `NotAllowedTagKey` | 単一タグ | タグキーがタグスキーマ上許容されない |
| `UnparseableTagValue` | 単一タグ | XMPの値をスキーマ定義もしくはフォールバックの型として解釈できない |
| `DuplicateSetValue` | 単一タグ | セットの要素値を解釈した結果、同じ値が複数存在する |
| `NotAllowedTagValue` | 単一タグ | 解釈したタグの値が、スキーマで定義された制約を満たさない |
| `MissingRequiredTag` | タグ全体 | 個々のタグの解釈後、そのコンテンツの有効なタグ中に必須タグが存在しない |


なお、単一タグスコープの異常について、同じタグキーに対しては1つの異常のみを診断に含めるものとする。
